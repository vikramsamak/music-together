# music-together — implementation plans

YouTube Music listening app: users create/join rooms by ID, chat, and listen together.
Functional-first; UI is intentionally unstyled until later.

## Architecture (decided)

| Piece | Choice |
| --- | --- |
| Frontend | `apps/web` — Next.js 16 (App Router, React 19, Tailwind 4, TS) |
| Backend | `apps/api` — NestJS 11 + `@nestjs/websockets` (socket.io gateway) |
| Realtime | socket.io rooms (single API instance, in-memory presence) |
| State store | Redis via Laragon — `127.0.0.1:6379`, no auth |
| Auth | None. Join by room ID; display name from `localStorage` (`mt.displayName`), else ephemeral `Guest-XXXX` |
| Track input | Paste YouTube/YT Music URL (search is a Phase 5 extra) |
| Playback control | Any room member may play/pause/seek/skip/add |
| Git | Single root repo (nested `.git`s were removed) |

**Ports:** web `:3000`, api `:3001` (socket.io CORS allows `http://localhost:3000`).

**Why NestJS owns realtime:** stable Next.js (16.4.x) has no WebSocket upgrade API
(`NextResponse.upgrade()` is still a draft RFC); NestJS has first-class WS gateways.

## Run

```bash
# Redis must be running (Laragon → Redis, port 6379, no password)
npm run dev          # turbo: api (3001) + web (3000) in watch mode
npm run build        # build both
npm run lint
```

Single workspace: `npm run dev -w api` / `npm run dev -w web`.
Single test: `npm run test -w api`.

## Redis keys

- `room:{id}` — hash: playback state (`currentVideoId`, `currentTrackId`, `playing`, `position`, `updatedAt`, `version`, meta)
- `room:{id}:queue` — list of JSON tracks `{ id, videoId, url, title, addedBy, addedAt }`
- `room:{id}:chat` — list of JSON messages, capped to last 100 (RPUSH + LTRIM)

## WS protocol (JSON, socket.io)

Client → server: `join`, `chat:send`, `queue:add`, `queue:remove`, `player:play`,
`player:pause`, `player:seek`, `player:next`, `player:prev`, `player:ended`
Server → client: `joined` (snapshot), `presence:update`, `chat:new`, `queue:update`,
`playback:update`, `queue:added`, `chat:sent`, `error`

`playback:update` carries `{ state, senderId, now }`; `state` is
`{ currentVideoId, currentTrackId, playing, position, updatedAt, version }`. Clients
treat incoming state idempotently (own echo is a no-op) so `next`/`prev`/`ended`
apply for the sender too.

## Cross-cutting constraints

- Browsers block audio autoplay until a user gesture: playback starts when someone clicks play.
- Playback sync = server-authoritative position + client drift correction (>2s drift → seek).
- `apps/web/AGENTS.md` nextjs-agent-rules block is auto-regenerated by `next dev` — do not delete.
- YouTube playback uses the IFrame embed API (no API key, ToS-sanctioned); stream extraction is out of scope.
